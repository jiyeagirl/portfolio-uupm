# PartLoop Product Spec

## 1. Overview

PartLoop는 소규모 제조사가 협력 공급사에 부품을 발주하고, 공급사가 수락하고 납품하기까지의
흐름을 한 화면에서 관리하는 B2B 수발주 웹 서비스다. 엑셀과 전화로 오가던 발주서를 상태가 있는
주문으로 바꾸는 것이 목적이다.

이 프로젝트는 워크스페이스가 정상 동작하는지 확인하기 위한 **테스트용 최소 프로젝트**다.
화면은 3개만 만들고, 기능 범위를 넓히지 않는다.

- **플랫폼**: Web (Business Console)
- **사용자**: 구매사 구매 담당자 1종류만 다룬다. 공급사 화면과 관리자 화면은 만들지 않는다.
- **데이터**: 전부 목업 데이터. 백엔드, 로그인, 실제 저장은 없다. 상태 변경은 화면 안
  컴포넌트 상태로만 처리한다.

## 2. Information Architecture

화면은 3개이고, 좌측 내비게이션으로 오간다. 상세 화면은 목록에서 행을 눌러 들어간다.

1. **발주 현황** (`orders`)
   - 상단 요약 4칸: 이번 달 발주 건수, 납품 대기, 지연, 이번 달 발주 금액
   - 발주 목록 표: 발주번호, 공급사, 품목 요약, 금액, 납기일, 상태
   - 상태 탭(전체 / 승인 대기 / 진행 중 / 납품 완료)과 발주번호, 공급사 검색
   - 행 클릭 시 발주 상세로 이동, 우측 상단 "발주 작성" 버튼으로 발주 작성으로 이동(상단 내비와 같은 이름)
2. **발주 작성** (`new-order`)
   - 공급사 선택, 납기일, 납품 장소, 메모
   - 품목 행 추가 / 삭제: 품목명, 규격, 수량, 단가, 행 금액은 수량 x 단가로 자동 계산
   - 우측에 발주 요약(공급사, 품목 수, 공급가액, 부가세, 총액)과 "발주 요청" 버튼
   - 발주 요청을 누르면 목록 첫 줄에 "승인 대기" 상태로 새 발주가 추가되고 발주 현황으로 돌아간다
3. **발주 상세** (`order-detail`)
   - 발주번호, 상태 배지, 공급사 정보, 납기일, 품목 표, 금액 합계
   - 진행 타임라인: 발주 요청, 공급사 수락, 출고, 납품 완료
   - 상태별 액션 버튼 1개: 승인 대기는 "발주 승인", 진행 중은 "납품 확인", 완료는 버튼 없음
   - 버튼을 누르면 상태와 타임라인이 즉시 바뀌고 목록에도 반영된다

## 3. Key Focus

- 3개 화면이 목업 데이터 위에서 끝까지 이어지는 것: 목록에서 작성하고, 목록에서 열고, 상세에서
  상태를 바꾸는 한 바퀴가 돌아야 한다.
- 표가 중심이다. 발주 목록과 품목 표의 밀도, 정렬, 숫자 표기(천 단위 구분, 우측 정렬)를 신경 쓴다.
- 상태 5개(승인 대기, 수락 대기, 진행 중, 지연, 납품 완료)의 의미와 색을 모든 화면에서 같게 쓴다.

## 4. Mock Data Guide

- 구매사: A테크. 공급사는 B소재, C정밀, D패키징, E전자, F금속 5곳 안에서 고른다.
- 발주 8~10건. 상태가 골고루 섞이게 하고, 지연 건이 최소 1건 있어야 한다.
- 품목은 볼트, 베어링, 기판, 포장 박스, 알루미늄 판재처럼 제조사가 실제로 발주할 법한 부품으로 한다.
- 담당자 이름과 연락처는 그럴듯하지만 가상으로 쓴다.

## 5. Out of Scope

공급사용 화면, 관리자 화면, 모바일 앱, 견적 비교, 결제, 정산, 문서 다운로드, 알림, 다국어.
