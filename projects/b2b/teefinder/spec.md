 TeeFinder Product Spec
1. Overview

TeeFinder는 골프 회원권 사업자가 회원권 구매 회원에게 제공하는 회원 전용 골프장 빈 티타임 통합 서비스다. 골프장 홈페이지를 하나씩 돌며 빈자리를 확인하던 일을 한 앱에서 처리하고, 취소티 알림을 받고, 골프장별 로그인 없이 앱 안에서 바로 예약 페이지로 넘어가는 것이 목적이다. 운영자는 관리자 웹에서 회원 승인, 골프장 수집 설정, 수집 모니터링, 푸시 발송을 한다.

이 프로젝트는 위시켓 공고의 핵심 기능만 골라 보여 주는 최소 목업이다. 화면은 앱 6개, 관리자 웹 5개로 제한하고 기능 범위를 넓히지 않는다.

플랫폼: 두 개의 표면
회원 앱 (Mobile App): 모바일 화면. 데스크톱 브라우저에서는 가운데에 390px 폭 휴대폰 프레임 안에 보여 준다.
관리자 웹 (Admin Console): 데스크톱 웹 화면.
진입 화면: 첫 화면에서 "회원 앱 보기 / 관리자 웹 보기"를 고르는 간단한 전환 스위치를 둔다.
사용자: 회원, 관리자 2종류.
데이터: 전부 목업 데이터. 백엔드, 실제 로그인, 실제 저장, 실제 수집, 실제 푸시는 없다. 상태 변경은 화면 안 컴포넌트 상태로만 처리하고, 앱과 관리자 웹이 같은 상태를 공유한다. (예: 관리자가 승인하면 앱의 승인 대기 화면이 풀린다.)
2. Information Architecture
2-1. 회원 앱 (화면 6개, 하단 탭: 홈 / 골프장 / 알림 / 내 정보)
로그인·가입·승인 대기 (app-login)
카카오 로그인, 애플 로그인 버튼(누르면 목업 회원으로 진입)
가입 신청 폼: 이름, 휴대폰, 회원권 번호, 약관·골프장 계정 보관 동의
신청 후 승인 대기 안내 화면. 승인 전에는 다른 탭을 눌러도 이 화면으로 돌아온다
반려되면 관리자가 입력한 반려 사유를 보여 주고 "재신청" 버튼 제공
시연용으로 하단에 "(시연) 승인됨 / 반려로 전환" 작은 토글을 둔다
홈: 통합 티타임 캘린더 (app-home)
주간 날짜 스트립, 날짜별 빈 티타임 수 표시
필터: 지역, 날짜, 가격대
골프장 카드별 시간 칩(예: 07:12), 코스, 그린피, 즐겨찾기 하트. 카드를 누르면 골프장 상세로 이동
골프장 목록·상세 (app-courses, app-course-detail)
목록: 이름 검색, 지역 필터, 전체 / 즐겨찾기 토글, 각 행에 오늘 잔여 티타임 수와 계정 등록 상태 배지
상세: 코스 구성, 날짜 선택 후 코스별 티타임 표(시간, 코스, 그린피, 예약 가능 / 마감), 즐겨찾기 토글
하단 고정 버튼 2개: "이 자리 알림 받기"(알림 조건 추가로 이동), "예약하러 가기"(인앱 웹뷰로 이동)
인앱 웹뷰 예약 (app-webview)
주소 표시줄과 닫기 버튼이 있는 브라우저 형태 화면에 목업 골프장 예약 사이트를 보여 준다
3단계가 1~2초 간격으로 자동 진행: ① 아이디·비밀번호 자동 입력 ② 로그인 완료 ③ 선택한 날짜·시간의 예약 페이지로 자동 이동
보안문자 골프장은 ①에서 멈추고 "보안문자를 직접 입력해 주세요" 입력창을 보여 준 뒤 입력하면 이어서 진행한다
취소티 알림 (app-alerts, 알림 탭 안에 서브탭 2개: 내 조건 / 알림함)
내 조건: 알림 조건 목록(골프장, 날짜, 시간대, 최대 가격, 켜기/끄기), "조건 추가" 폼
알림함: 취소티 알림 카드와 운영자 공지 카드, 읽음 처리. 취소티 카드를 누르면 해당 골프장 웹뷰로 이동
같은 자리는 한 번만 오는 것을 보여 주기 위해 중복 카드가 없어야 한다
시연용 "(시연) 취소티 푸시 도착" 버튼으로 화면 상단에 푸시 배너가 내려오게 한다
내 정보·골프장 계정·탈퇴 (app-profile)
회원 정보와 승인 상태
골프장 계정 관리: 골프장별 아이디·비밀번호 등록, 수정, 삭제. 비밀번호는 마스킹하고 "암호화되어 보관됩니다" 안내 문구를 둔다. 상태 배지는 정상 / 로그인 실패 / 보안인증 필요
탈퇴: 확인 모달에서 "등록한 골프장 계정 정보가 즉시 파기됩니다"를 보여 주고, 확인하면 파기 건수를 보여 준 뒤 로그인 화면으로 돌아간다
2-2. 관리자 웹 (화면 5개, 좌측 내비게이션)

내비게이션: 가입 승인 / 회원 관리 / 골프장 설정 / 수집 모니터링 / 푸시 발송

가입 승인 (admin-approvals)
승인 대기 목록(이름, 연락처, 회원권 번호, 신청일), 행 선택 시 우측 패널에서 승인 / 반려
반려 시 사유 입력 필수, 회원 앱에 안내됨
승인·반려 즉시 목록과 앱의 상태에 반영
회원 관리 (admin-members)
회원 표: 이름, 연락처, 회원권 정보, 가입일, 상태(정상 / 승인 대기 / 반려 / 이용 정지)
상태 필터, 이름·연락처 검색
회원 상세 패널에서 이용 정지 / 정지 해제(사유 입력)
골프장 설정 (admin-course-config)
좌측: 골프장 목록(검색, 상태 배지), "골프장 추가" 버튼
우측 설정 폼(운영자가 직접 수정): 기본 정보(이름, 지역, 코스), 도메인 URL, 로그인 방식(일반 / 보안문자), 로그인 Form Selector(아이디·비밀번호·버튼), 티타임 API 파라미터 매핑(날짜·시간·코스·그린피), 예약 페이지 이동 URL 패턴
설정 시험 실행 버튼: 저장 전에 단계별 결과(로그인 → 티타임 조회 → 파싱 결과 미리보기)를 보여 준다. 일부 골프장은 실패 결과와 오류 메시지가 나온다
저장 시 변경 이력 한 줄 추가. 골프장 추가는 같은 폼을 빈 상태로 쓴다
수집 모니터링 (admin-monitoring)
상단 요약: 전체 수집 성공률, 오류 골프장 수, 프록시 가용률, 마지막 수집 시각
수집 간격 선택(5분 / 2분 / 1분)과 간격별 예상 월 운영비 비교(예시 수치)
골프장별 표: 24시간 성공률, 마지막 성공 시각, 상태. 오류 골프장은 붉게 강조
오류 로그 목록과 "설정 수정하기" 버튼(골프장 설정 화면으로 바로 이동), 프록시 상태 요약
수집 실패 알림 기준(연속 N회 실패 시 운영자 알림) 설정
푸시 발송 (admin-push)
발송 폼: 대상(전체 / 지역별·골프장별 즐겨찾기 회원 그룹), 제목, 본문
수신 대상 수와 휴대폰 화면 미리보기
발송 후 이력 표 맨 위에 추가되고, 회원 앱 알림함에도 공지로 나타난다
3. Key Focus
두 표면이 한 흐름으로 이어지는 것: 앱에서 가입 신청 → 관리자 승인 → 티타임 조회와 알림 조건 설정 → 취소티 푸시 도착 → 웹뷰에서 자동 로그인과 예약 페이지 이동. 이 한 바퀴가 목업 데이터 위에서 끝까지 돌아야 한다.
운영자가 직접 고친다는 점이 보이는 것: 골프장 설정 화면이 코드 없이 URL·Selector·API 파라미터를 고치고 시험 실행까지 하는 화면으로 읽혀야 한다. 모니터링에서 오류를 발견하고 같은 흐름으로 고치는 모습이 한눈에 보여야 한다.
앱은 모바일 우선: 터치 영역 44px 이상, 하단 탭, 시간 칩과 필터는 가로 스크롤. 관리자 웹은 표 중심으로 밀도, 정렬, 숫자 표기(천 단위 구분, 우측 정렬)를 신경 쓴다.
상태 색의 일관성: 앱과 관리자 웹 모든 화면에서 같은 의미에 같은 색을 쓴다.
회원 상태: 승인 대기(주황), 승인·정상(초록), 반려(빨강), 이용 정지(회색)
골프장·수집 상태: 정상(초록), 점검 필요(주황), 오류(빨강), 보안인증 필요(파랑)
티타임 상태: 예약 가능(초록), 마감(회색), 취소티(파란 강조 배지)
4. Mock Data Guide
회원: 가상 이름 10~12명. 승인 대기 3명 이상, 반려 1명, 이용 정지 1명을 포함해 골고루 섞는다. 앱의 기본 시연 회원은 "김회원(승인됨)"이다. 연락처는 가상 번호(010-0000-XXXX)만 쓴다.
골프장: 가상 골프장 15~20곳을 지역별로 분포시키고 화면에는 "총 70곳"으로 표기한다. 실제 골프장명은 쓰지 않고 "블루힐 CC", "솔밭 레이크 CC", "한라 파인 CC"처럼 만든다. 코스는 골프장마다 2~3개(레이크 / 힐 / 밸리). 대부분 일반 로그인이고 2~3곳은 보안문자 필요.
티타임: 오늘부터 14일치. 골프장별 날짜마다 5~12개 시간(06:00~15:00), 코스, 그린피(주중 12만~18만 원대 / 주말 20만~28만 원대). 마감과 예약 가능이 섞이고 취소티 몇 건을 포함한다.
시연 회원 데이터: 즐겨찾기 4곳, 알림 조건 3개, 알림함 6건(읽음·안 읽음 혼합, 운영자 공지 2건 포함), 등록된 골프장 계정 4곳(정상 2, 로그인 실패 1, 보안인증 필요 1).
수집 모니터링: 골프장별 성공률은 대부분 95% 이상, 2~3곳은 50~90%, 1~2곳은 오류 상태(예: "로그인 선택자 불일치 – 홈페이지 개편 의심"). 오류 로그 10건 내외. 수집 간격별 월 운영비는 예시 수치로 두고 "실제는 견적 확정 후 안내" 문구를 작게 붙인다.
푸시 발송 이력: 4~5건.
5. Out of Scope
실제 서버, DB, 로그인(카카오·애플), 푸시(FCM), 크롤링·프록시, 암호화(KMS), 웹뷰 JS Injection (목업 연출로만 표현)
골프장 자동 회원가입, 엑셀 명부 자동 대조, 즐겨찾기 전용 별도 화면, 푸시 수신 세부 설정, 골프장 기본 정보 별도 관리 화면
결제, 정산, 예약 완료 처리, 골프장 100곳 이상 확장 화면, 다국어, 다크 모드
요구사항 정의서, ERD, API 명세서, 매뉴얼 등 문서 결과물
