# console 프리셋 레퍼런스

B2B 서비스, 관리자 화면, 운영 도구. 하루 종일 표와 숫자를 보는 사람이 쓰는 화면임. "예쁜 첫인상"보다 "100번째 사용에서도 빠른가"가 기준.

## 질의어 예시

| spec 업종 | 질의어 |
|---|---|
| 제조 발주, 수발주 | `B2B procurement purchase order supplier management` |
| 재고, 물류 | `inventory warehouse stock logistics` |
| 병원, 예약 관리 | `clinic appointment scheduling staff` |
| 부동산 중개 관리 | `real estate brokerage listing agent management` |
| 콘텐츠 운영, CMS | `content operations publishing editorial workflow` |
| 관제, 모니터링 | `monitoring operations realtime alert` |

## intake가 자동으로 버리는 것

랜딩 섹션 패턴, GSAP 스크롤 연출, 카드 hover 상승, 카드 전체 cursor-pointer, 2px 보조 버튼 테두리, 모달 blur, 본문 16px 규칙. 이유는 생성된 override에 적혀 있음.

## 보조 검색 기본 질의

```bash
python3 $S "<업종 단어>" --domain product -n 2          # Dashboard Style, Color Palette Focus 확인
python3 $S "status badge color not only" --domain ux -n 1
python3 $S "data table sortable" --domain ux -n 2
python3 $S "<차트 목적>" --domain chart -n 2           # 차트가 spec에 있을 때만
```

## 셸 선택지

같은 카테고리 안에서 같은 셸 연속 2개 금지. override에 고른 것과 배제한 2개를 적음.

| 셸 | 맞는 경우 | 주의 |
|---|---|---|
| S1 흰 좌측 레일 (220~240px) | 메뉴 4~10개, 일반 업무 도구 | 기본값. 레일 상단에 조직 전환, 하단에 사용자 |
| S2 상단 바 + 화면 내 탭 | 메뉴 2~4개, 화면이 넓어야 하는 표 중심 | 상단 바는 56px 이하, 무채색 또는 잉크 |
| S3 아이콘 레일 (64px) + 보조 패널 | 메뉴가 많고 2단계 구조 | 아이콘만 두지 말고 hover 툴팁 또는 보조 패널에 라벨 |
| S4 다크 좌측 레일 | 관제, 야간 운영, 금융 트레이딩 | 워크스페이스에 이미 많음. 도메인 근거가 있을 때만 |
| S5 마스터 디테일 (목록 고정 + 우측 상세) | 건별 처리가 많은 큐 업무 (문의, 승인, 검수) | 목록 폭 360~420px |

## 화면 패턴

### 목록, 현황 화면
- 페이지 헤더: 제목 + 주 액션 버튼 1개. 회색 히어로 띠 금지 (표가 아래로 밀림)
- KPI는 3~5개. 카드 여러 장보다 한 덩어리를 구분선으로 나누는 쪽 우선
- **KPI 보조 문구는 집계 기준 설명만** ("수락 대기, 진행 중, 지연 포함"처럼 spec의 상태명 그대로). 숫자를 다시 쪼갠 내역, 특정 레코드 이름, 근거 없는 증감률 금지. 필요 없으면 생략
- 필터: 상태 탭(건수 포함) + 검색 + 기간. 탭 건수는 같은 데이터로 계산되는 값이라 허용
- 표 규칙
  - 숫자 열 우측 정렬 + tabular-nums, 단위는 열 제목에 (`금액 (원)`, `금액 (VAT 포함)`)
  - 주 정보 + 보조 정보는 **두 줄 셀**로 쌓아 열 수를 줄임 (공급사명 위, 품목 요약 아래)
  - 클릭해서 들어가는 ID는 링크처럼 보이게 (accent 색 또는 밑줄 hover)
  - 행 높이 44~56px, 헤더는 배경 한 톤 다르게
  - 행 단위 파생값(D-day, 지연 일수)은 허용. 레코드 필드 하나로 계산되므로
  - 빈 상태: 무엇이 없는지 + 다음 행동 한 줄
- 상태 배지: 색 + 아이콘 + 텍스트 3중 표기. 색만으로 구분 금지

### 작성, 편집 화면
- 2단: 좌측 입력(섹션별 패널) + 우측 고정 요약(합계, 주 버튼)
- 라벨은 입력 위, 필수 표시는 별표 또는 "필수" 텍스트 중 하나로 통일
- 반복 행(품목 등)은 표 형태 입력, 행 금액 자동 계산, 행 추가와 삭제
- 주 버튼이 비활성이면 이유를 버튼 아래에 표시
- 입력칸 모서리 6~8px. 알약 모양(완전 둥근) 입력칸 금지 (소비자 앱 인상)

### 상세 화면
- 헤더: ID + 상태 배지 + 주 액션 1개 (보조 액션은 secondary)
- 핵심 메타(납기, 장소, 담당) 한 줄 스트립
- 본문 좌측: 주 표, 우측: 타임라인과 관계 정보(거래처, 담당자)
- 예외 상태(지연, 반려)는 상단 배너로 원인 + 다음 행동

## 파일럿에서 리뷰어가 잡은 것 (PartLoop, 2026-10)

- **같은 집합에 이름 하나**: 필터 탭, KPI, 배지가 같은 묶음을 다른 이름으로 부르면 숫자가 어긋나 보임. 탭 묶음 이름이 배지 상태명과 겹치면(탭 "진행 중 6" vs 배지 "진행 중" 3행) 탭 이름을 KPI 쪽 이름으로 맞춤. spec이 이름을 고정했으면 spec 수정을 제안함
- **로그인 사용자와 권한**: 승인 버튼을 보여주면 로그인 사용자가 승인권자여야 함. 승인 주체를 다른 직책으로 적으면 권한 모순이 생김
- **할 수 없는 행동을 주 버튼으로 두지 않음**: 지금 할 수 있는 행동(공급사 연락)을 채운 주 버튼으로, 불가능한 행동은 회색 secondary로 내리고 이유를 표시
- **미완료 단계 문구는 완료형 금지**: 타임라인의 오지 않은 단계는 "출고 전"처럼 씀
- **통화 표기 하나로**: 표 안은 열 제목에 "(원)", 표 밖 합계와 KPI는 "원" 접미 하나로 통일
- **크기와 서체가 다른 라벨과 숫자는 baseline 정렬**: 중앙 정렬은 글자 바닥이 어긋남
- **두 줄 셀을 쓰면 남는 폭 처리**: 합친 열이 짧아 금액 열까지 빈 띠가 생기면 최대 폭을 주거나 요청일, 담당자 같은 열을 추가
- **단위가 다른 수량을 합산하지 않음**: "외 1건 수량 52"처럼 서로 다른 품목 수량을 더한 값은 의미가 없음
- **브라우저 기본 날짜 입력 표시 금지**: 언어 설정마다 형식이 달라짐. 워크스페이스 표기(2026.10.07 (수))로 보여주고 눌렀을 때만 기본 달력

## 상태 색 정하기

- 신호등(초록 완료, 주황 대기, 빨강 지연 또는 오류) + 중립(회색 대기) + 진행(브랜드 accent 계열)
- 배경은 연한 틴트, 글자는 같은 계열의 진한 톤으로 대비 4.5:1 이상
- 보라, 분홍 그라데이션 금지 (UUPM 공통 anti-pattern)

## 타이포, 밀도

- 본문 13.5~14px / 행간 20px 전후. 앞선 프로젝트와 같은 쌍 금지
- 페이지 제목 22~26px, KPI 숫자 24~30px (디스플레이 폰트)
- 그림자는 최소 단계까지만. 계층은 1px 보더와 배경 명도로

## 모션

- 화면 전환 페이드 1개 (180~260ms), 상태 변화 시 배지 교체 피드백, 토스트
- 스크롤 등장 연출, 숫자 카운트업, 카드 순차 등장 금지

## 리뷰어가 보는 것

`review-domain`과 `review-ux`는 이 파일의 "화면 패턴", "상태 색" 절을 판정 기준으로 씀.
