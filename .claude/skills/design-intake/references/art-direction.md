# 아트 디렉션 (web, app 필수)

UUPM은 "틀리지 않게"까지만 정해줌. 업종에 맞는 색, 폰트, 금지 패턴은 나오지만 "이 서비스답게, 예쁘게"는 나오지 않음. 콘솔은 틀리지 않는 것이 곧 좋은 것이라 그걸로 충분하지만, 사용자가 직접 쓰는 웹과 앱은 그 위에 인상이 있어야 함. 이 문서는 그 인상을 만드는 단계임.

## 프리셋별 품질 기준

| 프리셋 | 기준 | 이유 |
|---|---|---|
| console | **절제.** 빠르게 읽히고 틀리지 않으면 통과. 장식, 일러스트, 큰 색 면적은 감점 | 실무 도구에 디자인 공수를 많이 들인 티가 나면 오히려 어색함 |
| web, app | **표현.** 틀리지 않는 것은 최소 조건. 3초 안에 이 서비스만의 인상이 보여야 통과 | 사용자가 고르는 서비스라 첫인상이 곧 품질 |

## 절차 (design-intake 4.5단계)

### 1. 무드 문장
- spec이 "피할 것"만 적었더라도 **원하는 감도를 긍정형 형용사 3개**로 정함. 예: "따뜻한, 수다스러운, 잡지 같은"
- "차분한, 깔끔한, 무난한"처럼 빼기 방향 단어만 3개면 다시 고름. 최소 1개는 성격이 있는 단어여야 함 (발랄한, 에디토리얼한, 손글씨 같은, 대담한, 장난스러운 등)

### 2. 레퍼런스 3개
- 같은 업종 실제 서비스 2개 + **다른 업종 1개**(감도를 빌려올 곳)
- 레퍼런스마다 **가져올 구체 패턴 1~2개**를 적음. "깔끔함" 같은 추상어 금지. 예: "오늘의집 커뮤니티: 사진이 카드 위쪽 전체를 차지하고 제목이 사진 아래 2줄", "29CM: 섹션 제목을 아주 크게, 본문은 작게 해서 크기 대비로 위계"
- 브랜드 복제 금지: 로고, 고유 색 조합, 마스코트, 고유 문구는 가져오지 않음. 레이아웃과 위계 방식만 가져옴
- **실제 화면을 열어서 확인함.** 브라우저로 레퍼런스를 열어 캡처를 보고, 제목 크기, 사진 비율, 행 구성, 여백 같은 패턴을 구체적으로 적음. 기억으로 적은 레퍼런스는 구조가 코드까지 내려가지 못해 화면이 무난해짐
- 접근이 막히거나 열리지 않는 곳(권한 거부, 오류 페이지)은 우회하지 않음. **열리는 1곳만 참고하고 넘어가지 말고, 안 열린 곳을 전부 사용자에게 나열해 캡처를 요청함.** 사용자가 캡처를 붙이면 "(실측)", "열리는 것만 참고"라고 하면 그때 "(미확인, 기억 기반)"으로 표시함. 사용자 답을 받기 전에는 미확인으로 확정하지 않음
- 실측 레퍼런스는 최소 1개
- 확인한 레퍼런스가 의외로 단순하면(예: 당근의 목록은 칩 없이 제목과 한 줄 본문뿐) 그 단순함도 가져올 패턴임

업종별 레퍼런스 후보 (출발점일 뿐, 맞는 것을 새로 찾아도 됨)

| 업종 | 같은 업종 | 다른 업종 감도 후보 |
|---|---|---|
| 동네, 커뮤니티 | 당근 동네생활, 오늘의집 커뮤니티, 블라인드 | 29CM 매거진, 브런치 |
| 예약, 클래스 | 프립, 솜씨당, 에어비앤비 | 매거진 B, 쿠키런 공식 사이트 같은 브랜드 사이트 |
| 쇼핑 | 29CM, 무신사, 컬리 | 에디토리얼 매거진 |
| 금융, 자산 | 토스, 뱅크샐러드 | 애플 건강 앱 |
| 건강, 습관 | 눔, 캐시워크 | 듀오링고 |
| 반려동물 | 펫프렌즈, 핏펫 | 오늘의집 |
| 여행, 지도 | 마이리얼트립, 트리플 | 네이버 지도 |

### 3. 시그니처 요소 2개 이상
아래 메뉴에서 2개 이상 고르고, 이 서비스에서 **구체적으로 어떻게** 쓸지 적음. 화면 3개 중 최소 2개에 보여야 함.

| 메뉴 | 예시 |
|---|---|
| 워드마크, 브랜드 마크 | 글자만 있는 로고가 아니라 형태가 있는 마크 (SVG 직접 작성). 혼집이면 지붕 모양이 들어간 'ㅎ' |
| 그래픽 모티프 | 반복되는 도형, 선, 패턴. 동네 지도 선, 창문 격자, 손으로 그린 밑줄 |
| 큰 색 면적 | 브랜드 색을 버튼에만 쓰지 않고 히어로, 섹션 배경, 카드 상단 띠처럼 넓은 면으로 씀 (면적 15% 이상) |
| 타이포 대비 | 섹션 제목을 본문의 2.5배 이상으로 키우거나, 한글 디스플레이 폰트(`font-map.md`)를 제목에 적극 사용 |
| 사진 처리 방식 | 고정 비율, 라운드 크기, 겹침, 프레임, 캡션 위치를 일관되게 (사진이 아직 없어도 자리의 형태와 처리 방식은 정함) |
| 일러스트, 이모티콘 세트 | 빈 상태, 주제 아이콘을 프로젝트 전용 SVG로 (이모지 금지) |
| 마이크로 인터랙션 | 공감, 저장, 완료 같은 핵심 행동 1개에 기억에 남는 피드백 |

### 3.5 구조 변경 1개 이상
시그니처를 얹기만 하면 같은 템플릿(상단 바, 배너, 번호 목록, 탭, 카드 목록, 우측 박스) 위의 장식이 됨. 프리셋의 흔한 구성에서 **레이아웃 자체를 바꾼 곳**을 1개 이상 정함. 예: 사진 글만 큰 카드로 올리고 나머지는 행으로 섞음, 사이드 박스를 화면 흐름 안으로 옮김, 히어로를 글자 배너에서 일러스트와 제목이 맞물리는 구성으로 바꿈.

### 3.6 한글 디스플레이 폰트
web, app은 `font-map.md`에서 한글 제목 폰트 1개를 골라 실제로 설치하고 적용함. 쓰지 않기로 하면 이유를 적음.

### 4. 빼기와 더하기의 균형
- `design.md`의 "버림"에 적은 항목 수만큼 "더한 것"에도 적음. 버리기만 하면 무난해짐
- 소비자 화면의 단순 카운트(이웃 수, 오늘 새 글 수, 참여 인원)는 목업 데이터로 써도 됨. "검증 불가 수치 금지"는 콘솔 KPI 보조 문구 규칙이고 소비자 화면의 사회적 증거에는 적용하지 않음
- 히어로나 소개 띠는 서비스 화면이라도 홈 상단에 한 줄짜리 브랜드 영역으로 둘 수 있음 (첫 화면에 실제 콘텐츠가 보이는 한)

## 무난함 점검표 (빌더와 review-visual 공용)

3개 이상 해당하면 무난한 화면임. 하나씩 고침.

- [ ] 화면에서 브랜드 색 면적이 5% 미만 (버튼에만 있음)
- [ ] 제목과 본문 크기 차이가 1.5배 미만
- [ ] 모든 목록 항목이 같은 모양, 같은 무게로 반복됨 (강조되는 항목 없음)
- [ ] 로고가 글자뿐이고 형태가 없음
- [ ] 회색 테두리 카드가 화면 대부분을 차지함
- [ ] 항목 하나에 칩, 배지가 3개 이상
- [ ] 빈 상태, 사진 자리, 아이콘이 기본 아이콘 세트 그대로라 서비스 고유의 그림이 하나도 없음
- [ ] 레퍼런스 서비스 캡처 옆에 놓으면 확연히 밋밋함

## design.md에 적을 형식 (web, app)

```markdown
## 아트 디렉션
무드: <형용사 3개>
레퍼런스:
- <서비스>(실측): <가져온 패턴, 수치로>
- <서비스>(미확인): <기억 기반 패턴>
- <다른 업종 서비스>: <가져온 감도>
시그니처:
- <메뉴 항목>: <이 서비스에서 구체적으로 어떻게>
- <메뉴 항목>: <...>

한글 디스플레이: <폰트 이름, 또는 "쓰지 않음(이유)">

## 구조 변경
- <흔한 구성에서 바꾼 레이아웃 1개 이상>

## 더한 것
- <버림과 같은 수 이상>
```

`pre-write-design-gate.mjs`가 web, app 프로젝트에서 "## 아트 디렉션", "한글 디스플레이:" 줄, "## 구조 변경"(1줄 이상), "## 더한 것"(2줄 이상), 실측 레퍼런스 표기를 확인함.
